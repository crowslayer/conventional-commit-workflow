Conventional Commit Workflow

A defensive, evidence-based Git commit management agent skill for AI coding assistants. Analyzes your working tree, groups changes into atomic commits, applies Conventional Commits, evaluates semantic-release impact, and executes only when you explicitly authorize it.

v2.5.0 MIT MCP compatible Cursor / Windsurf / Copilot / Claude
GitHub npm

Install as MCP server (recommended)

Add to your MCP client config (Claude Desktop, Cursor, etc.):

{
  "mcpServers": {
    "conventional-commit-workflow": {
      "command": "npx",
      "args": ["-y", "conventional-commit-workflow-mcp"]
    }
  }
}

No Vercel hosting needed: the server runs locally so it can access your Git repository.

Use as standalone skill (system prompt)

Copy the contents of skills/v2.0.0/system_prompt.md into your .cursorrules, Copilot instructions, Claude Project instructions, or Custom GPT system prompt.

git clone https://github.com/crowslayer/conventional-commit-workflow.git
cat conventional-commit-workflow/skills/v2.0.0/system_prompt.md

Safety guarantees

  • Never runs git reset --hard, git checkout -- ., or git restore .
  • Never runs git add . or git add -A
  • Never amends, rebases, pushes, or rewrites history without explicit authorization
  • Never bypasses Git hooks
  • Execution requires explicit user authorization

Why not host the MCP server on Vercel?

The skill's tools operate on your local Git working tree (git status, git diff, file reads). A remote server on Vercel cannot access your repository, so it would be useless and unsafe. Distribution via npm + npx is the standard for local MCP servers. Vercel is used here only for this documentation page.
